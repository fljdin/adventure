# Workflow Rules

## KISS
No over-engineering. Prefer lightweight, idiomatic solutions over complex patterns.

## Atomic commits
Small, focused commits. One commit per logical change: preparatory refactor, feature implementation, or fix. Each commit has a clear intent.

## Conventional commits
Use conventional commit format. Omit descriptions when the title is self-documenting.

## TDD
Always write a lightweight failing test before starting implementation.

## No remote push
Never push to remote (neither main nor feature branches). The author handles rebasing and pushing manually.
